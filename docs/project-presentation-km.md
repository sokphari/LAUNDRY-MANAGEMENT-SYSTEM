# ប្រព័ន្ធគ្រប់គ្រងហាងបោកគក់
## ឯកសារបង្ហាញគម្រោង

### ១ — ទិដ្ឋភាពទូទៅនៃគម្រោង

**ប្រព័ន្ធគ្រប់គ្រងហាងបោកគក់** គឺជាកម្មវិធីគេហទំព័រសម្រាប់គ្រប់គ្រងការងារប្រចាំថ្ងៃរបស់ហាងបោកគក់មួយ។ ប្រព័ន្ធនេះប្រមូលផ្តុំព័ត៌មានអតិថិជន សេវាកម្មបោកគក់ ការបញ្ជាទិញ ស្ថានភាពការងារ ការទូទាត់ បង្កាន់ដៃ របាយការណ៍ សកម្មភាពបុគ្គលិក និងការបម្រុងទុកទិន្នន័យនៅកន្លែងតែមួយ។

**អ្នកប្រើប្រាស់គោលដៅ៖** ម្ចាស់ហាង អ្នកគ្រប់គ្រង និងបុគ្គលិកហាងបោកគក់។

**ចំណុចសម្រាប់អ្នកធ្វើបទបង្ហាញ៖** ណែនាំគម្រោងនេះជាឧបករណ៍គ្រប់គ្រងប្រតិបត្តិការ ចាប់ពីពេលទទួលខោអាវ រហូតដល់ប្រគល់ខោអាវជូនអតិថិជនវិញ។

### ២ — ហេតុអ្វីបង្កើតគម្រោងនេះ?

ហាងបោកគក់ត្រូវរក្សាទុកព័ត៌មានទំនាក់ទំនងអតិថិជន ព័ត៌មានខោអាវ កាលបរិច្ឆេទយក សេវាកម្ម តម្លៃ ការទូទាត់ និងដំណើរការការបញ្ជាទិញឱ្យមានរបៀបរៀបរយ។ ប្រសិនបើព័ត៌មានទាំងនេះនៅលើក្រដាស ឬកត់ត្រាដាច់ដោយឡែក ការស្វែងរកការបញ្ជាទិញ និងការពិនិត្យប្រាក់នៅសល់អាចចំណាយពេលច្រើន។

ប្រព័ន្ធនេះផ្តល់កន្លែងរួមមួយសម្រាប់កត់ត្រា និងតាមដានការងារ។ វាត្រូវបានបង្កើតឡើងដើម្បីជួយបុគ្គលិកស្វែងរកព័ត៌មានបានលឿន គណនាតម្លៃឱ្យមានភាពស៊ីសង្វាក់គ្នា និងជួយម្ចាស់ហាងពិនិត្យសកម្មភាពរបស់ហាង។

### ៣ — ប្រព័ន្ធអាចធ្វើអ្វីបានខ្លះ?

- រក្សាទុកព័ត៌មានទំនាក់ទំនងអតិថិជន និងតម្លៃសេវាកម្ម។
- បង្កើតការបញ្ជាទិញដែលមានសេវាកម្មមួយ ឬច្រើន និងបរិមាណ។
- តាមដានស្ថានភាពការបញ្ជាទិញ៖ **បានទទួល → កំពុងដំណើរការ → រួចរាល់ → បានប្រគល់** ឬ **បានបោះបង់**។
- កត់ត្រាប្រាក់កក់ ការទូទាត់បន្ថែម ការសងប្រាក់ និងប្រាក់នៅសល់។
- បោះពុម្ពបង្កាន់ដៃទទួលខោអាវ និងបង្កាន់ដៃទូទាត់ប្រាក់។
- បង្ហាញស្ថិតិប្រតិបត្តិការ របាយការណ៍ និងសកម្មភាពបុគ្គលិកតាមសិទ្ធិដែលបានកំណត់។
- រក្សាកំណត់ហេតុសវនកម្ម និងការបម្រុងទុកទិន្នន័យ។

### ៤ — អ្នកប្រើប្រាស់ និងសិទ្ធិចូលប្រើ

**អ្នកគ្រប់គ្រង / ម្ចាស់ហាង (Admin)**

- មើលព័ត៌មានសរុបរបស់ហាង និងសកម្មភាពបុគ្គលិក។
- គ្រប់គ្រងគណនីបុគ្គលិក សិទ្ធិតាមតួនាទី និងសេវាកម្ម។
- ប្រើរបាយការណ៍ កំណត់ហេតុសវនកម្ម និងមុខងារបម្រុងទុក/ស្ដារទិន្នន័យ។

**បុគ្គលិក (Staff)**

- មើលស្ថិតិ និងសកម្មភាពការងារផ្ទាល់ខ្លួននៅលើផ្ទាំងគ្រប់គ្រង។
- បំពេញការងារប្រចាំថ្ងៃជាមួយអតិថិជន ការបញ្ជាទិញ និងការទូទាត់ តាមសិទ្ធិដែលបានផ្ដល់។
- អាចមើលបញ្ជីសេវាកម្មជាលំនាំដើម។
- អាចជួយដំណើរការការបញ្ជាទិញរបស់ហាងដែលបង្កើតដោយមិត្តរួមការងារ ប្រសិនបើមានសិទ្ធិប្រតិបត្តិការដែលពាក់ព័ន្ធ។

ប្រព័ន្ធពិនិត្យសិទ្ធិនៅផ្នែកម៉ាស៊ីនមេ។ Admin អាចកំណត់សិទ្ធិសម្រាប់តួនាទី Staff និងកែសិទ្ធិជាក់លាក់សម្រាប់បុគ្គលិកម្នាក់ៗ។ មុខងារបម្រុងទុក និងស្ដារទិន្នន័យអនុញ្ញាតតែ Admin ប៉ុណ្ណោះ។

### ៥ — លំហូរការងារទូទៅរបស់ហាង

```text
ស្វែងរក ឬបន្ថែមអតិថិជន
        ↓
បង្កើតការបញ្ជាទិញ និងជ្រើសសេវាកម្ម / បរិមាណ
        ↓
ពិនិត្យតម្លៃសរុប កត់ត្រាប្រាក់កក់បើមាន ហើយបង្កើតការបញ្ជាទិញ
        ↓
បានទទួល → កំពុងដំណើរការ → រួចរាល់
        ↓
ទទួលប្រាក់នៅសល់ → កំណត់ថាបានប្រគល់ → បោះពុម្ពបង្កាន់ដៃ
```

តម្លៃសេវាកម្ម និងឯកតាគិតថ្លៃត្រូវបានរក្សាទុកជាមួយការបញ្ជាទិញនៅពេលបង្កើត។ ការកែតម្លៃក្នុងបញ្ជីសេវាកម្មនៅពេលក្រោយ មិនកែប្រែព័ត៌មានរបស់ការបញ្ជាទិញចាស់ទេ។ ប្រព័ន្ធតម្រូវឱ្យទូទាត់ប្រាក់ពេញមុនពេលកំណត់ការបញ្ជាទិញថា បានប្រគល់។

### ៦ — ម៉ូឌុលសំខាន់ៗ

| ម៉ូឌុល | មុខងារសំខាន់ៗ |
|---|---|
| **ផ្ទាំងគ្រប់គ្រង** | តម្រងតាមកាលបរិច្ឆេទ ស្ថិតិការបញ្ជាទិញ/ការទូទាត់ និងក្រាហ្វ។ Admin មើលទិន្នន័យហាងទាំងមូល; Staff មើលទិន្នន័យផ្ទាល់ខ្លួន។ |
| **អតិថិជន** | ស្វែងរក បង្កើត មើល និងកែប្រែព័ត៌មានអតិថិជន; រក្សាទុកព័ត៌មានទំនាក់ទំនង និងប្រវត្តិ។ |
| **សេវាកម្ម** | បង្កើត និងកែប្រែតម្លៃ ឯកតាគិតថ្លៃ ស្វែងរកតាមស្ថានភាព និងបើក/បិទសេវាកម្ម។ ជាលំនាំដើម Staff អាចមើលបានតែប៉ុណ្ណោះ។ |
| **ការបញ្ជាទិញ** | បង្កើត ស្វែងរក តម្រង កែប្រែការបញ្ជាទិញដែលអាចកែបាន ផ្លាស់ប្តូរស្ថានភាព មើលប្រវត្តិ និងបោះពុម្ពបង្កាន់ដៃទទួលខោអាវ។ |
| **ការទូទាត់** | ពិនិត្យប្រតិបត្តិការ និងការសងប្រាក់ កត់ត្រាការទូទាត់ដែលមានសិទ្ធិ ផ្ទៀងផ្ទាត់ប្រាក់នៅសល់ មើល/បោះពុម្ពបង្កាន់ដៃ និងនាំចេញទិន្នន័យ។ |
| **របាយការណ៍** | តម្រងតាមកាលបរិច្ឆេទ ពិនិត្យការបញ្ជាទិញ ការទូទាត់ ការសងប្រាក់ ប្រាក់នៅសល់ និងសមិទ្ធផលសេវាកម្ម; នាំចេញជា PDF ឬ CSV។ |
| **អ្នកប្រើប្រាស់ និងប្រវត្តិរូប** | Admin គ្រប់គ្រងគណនី និងសិទ្ធិ; អ្នកប្រើប្រាស់ម្នាក់ៗកែប្រែប្រវត្តិរូបផ្ទាល់ខ្លួន។ |
| **កំណត់ហេតុសវនកម្ម និងការជូនដំណឹង** | ពិនិត្យព្រឹត្តិការណ៍សុវត្ថិភាព/គណនី ចំនួនការជូនដំណឹងមិនទាន់អាន និងសកម្មភាពក្នុងប្រព័ន្ធ។ |
| **បម្រុងទុក និងស្ដារទិន្នន័យ** | Admin បង្កើត/ទាញយកឯកសារបម្រុងទុក កំណត់កាលវិភាគ និងស្ដារឯកសារបន្ទាប់ពីបញ្ជាក់។ |

សិទ្ធិប្រើប្រាស់ជាក់ស្តែងអាចខុសគ្នាតាមសិទ្ធិដែលបានកំណត់។ មុខងារបម្រុងទុក និងស្ដារទិន្នន័យអនុញ្ញាតតែ Admin ប៉ុណ្ណោះ។

### ៧ — ការការពារដំណើរការអាជីវកម្ម

- ពាក្យសម្ងាត់ត្រូវបានរក្សាទុកជាទម្រង់ Hash; ការចូលប្រើប្រើ Session ខាងម៉ាស៊ីនមេ និងកំណត់ចំនួនការព្យាយាមចូល។
- សំណួរទៅមូលដ្ឋានទិន្នន័យប្រើ PDO Prepared Statements ហើយទម្រង់ដែលកែប្រែទិន្នន័យប្រើការការពារ CSRF។
- ម៉ាស៊ីនមេពិនិត្យតួនាទី និងសិទ្ធិមុនអនុញ្ញាតសកម្មភាពដែលត្រូវបានការពារ។
- ការកែប្រែការបញ្ជាទិញ ការទូទាត់ ការសងប្រាក់ និងសកម្មភាពសំខាន់ៗរបស់គណនី/សុវត្ថិភាពត្រូវបានកត់ត្រាក្នុង Audit Logs។
- ចំនួនទូទាត់ត្រូវបានផ្ទៀងផ្ទាត់ជាមួយប្រាក់នៅសល់របស់ការបញ្ជាទិញ។
- ទំនិញក្នុងប្រវត្តិការបញ្ជាទិញរក្សាឈ្មោះសេវាកម្ម ឯកតា និងតម្លៃដើម។
- ឯកសារបម្រុងទុករក្សាទុកក្រៅថតសាធារណៈ; ការស្ដារទិន្នន័យត្រូវការការបញ្ជាក់ និងបង្កើតច្បាប់ចម្លងសុវត្ថិភាពមុន។

### ៨ — អត្ថប្រយោជន៍នៃគម្រោង

- **ការងារមានរបៀបរៀបរយជាងមុន៖** ព័ត៌មានអតិថិជន និងការបញ្ជាទិញស្ថិតនៅជាមួយគ្នា។
- **ស្វែងរកបានលឿន៖** បុគ្គលិកអាចស្វែងរកតាមលេខកូដការបញ្ជាទិញ ឈ្មោះអតិថិជន ឬលេខទូរស័ព្ទ។
- **តាមដានការទូទាត់បានច្បាស់៖** ឃើញប្រាក់ដែលបានបង់ ការសងប្រាក់ និងប្រាក់នៅសល់។
- **តម្លៃគណនាស៊ីសង្វាក់គ្នា៖** ប្រព័ន្ធគណនាតម្លៃតាមសេវាកម្ម បរិមាណ និងតម្លៃដែលបានរក្សាទុក។
- **ធ្វើការជាក្រុម និងមានការទទួលខុសត្រូវ៖** បុគ្គលិកអាចជួយការបញ្ជាទិញរួម ខណៈផ្ទាំងគ្រប់គ្រង និងរបាយការណ៍បង្ហាញសកម្មភាពរបស់មនុស្សម្នាក់ៗ។
- **ម្ចាស់ហាងមើលការងារបានច្បាស់៖** ផ្ទាំងគ្រប់គ្រង របាយការណ៍ ការជូនដំណឹង និងកំណត់ហេតុសវនកម្មជួយត្រួតពិនិត្យហាង។
- **មានផ្លូវស្ដារទិន្នន័យ៖** ការបម្រុងទុកដោយដៃ និងតាមកាលវិភាគជួយការពារទិន្នន័យប្រតិបត្តិការ។

មុខងារទាំងនេះជួយដល់ការសម្រេចចិត្តប្រចាំថ្ងៃ ប៉ុន្តែមិនជំនួសការត្រួតពិនិត្យរបស់បុគ្គលិក ឬផែនការបម្រុងទុកទៅទីតាំងផ្សេងបានទេ។

### ៩ — បច្ចេកវិទ្យា និងរចនាសម្ព័ន្ធ

- **ផ្នែកម៉ាស៊ីនមេ៖** PHP 8, PDO និង MySQL។
